Lesson 1

One Table Is Not Enoughجدول واحد لا يكفي

By the end of this lesson you will be able to say what a flat file is and when it is the right choice, find the repetition it forces, and name the three things that go wrong because of it: the update, insert and delete anomalies.

في نهاية هذا الدرس ستستطيع أن تقول ما الملف المسطّح ومتى يكون الخيار الصحيح، وأن تجد التكرار الذي يفرضه، وأن تسمّي الأشياء الثلاثة التي تفسد بسببه: شذوذ التحديث، وشذوذ الإضافة، وشذوذ الحذف.

The setting. The faculty has asked Matt for a simplified library database to store the department's books (see the chapter home). Before Matt draws anything, the department already keeps a list of its books in one table. This lesson looks hard at that table. No earlier lesson is needed.

السياق. طلبت الكلية من مات قاعدة بيانات مبسّطة لمكتبة تحفظ كتب القسم (انظر صفحة الفصل). وقبل أن يرسم مات أي شيء، يحتفظ القسم أصلًا بقائمة كتبه في جدول واحد. هذا الدرس يتأمّل ذلك الجدول جيّدًا. لا يلزمك أي درس سابق.

  • Define a flat file database and recognise one, in plain text or as a table.
  • تعريف قاعدة بيانات الملف المسطّح والتعرّف عليها، نصًّا عاديًّا كانت أو جدولًا.
  • List the honest advantages of a flat file, and the disadvantages that limit it.
  • سرد المزايا الحقيقية للملف المسطّح، والعيوب التي تحدّ منه.
  • Point to the repeated fact in a flat table and explain how repetition leads to inconsistency.
  • الإشارة إلى الحقيقة المكرّرة في جدول مسطّح، وشرح كيف يقود التكرار إلى عدم الاتّساق.
  • Name the update, insert and delete anomaly in a given scenario.
  • تسمية شذوذ التحديث والإضافة والحذف في حالة معطاة.

1 · The flat file١ · الملف المسطّح

The department's book list is one table. The author and the book sit side by side in every row. Nothing else exists: no second table, no link, no rules. Is that a database at all?

قائمة كتب القسم جدول واحد. المؤلف والكتاب يجلسان جنبًا إلى جنب في كل صفّ. ولا شيء غير ذلك: لا جدول ثانٍ، ولا رابط، ولا قواعد. فهل هذه قاعدة بيانات أصلًا؟

Yes — the simplest kind. It has a name of its own.

نعم — أبسط أنواعها. ولها اسم خاص بها.

Definition. A flat file database is a type of database that stores all its data in a single table.

تعريف. قاعدة بيانات الملف المسطّح (Flat File Database) نوع من قواعد البيانات يحفظ كل بياناته في جدول واحد.

One line, one recordسطر واحد، سجلّ واحد

A flat file is usually plain text. Each line holds only one record, and the values on the line are separated by a mark such as a comma. The same BOOK_LIST, saved as a file, looks like this:

الملف المسطّح عادةً نصّ عادي. كل سطر فيه يحمل سجلًّا (Record) واحدًا فقط، وتفصل بين قيم السطر علامة كالفاصلة. هكذا يبدو BOOK_LIST نفسه محفوظًا في ملف:

AD0001,Oscar Wilde,A Vision
AD0002,Leo Tolstoy,War and Peace
AD0003,Oliver Goldsmith,Citizen of the World
AD0003,Oliver Goldsmith,Androcles and the Lion

Definition. A record is everything stored about one item — one line of the file, one row of the table.

تعريف. السجلّ هو كل ما يُحفظ عن عنصر واحد — سطر واحد في الملف، وصفّ واحد في الجدول.

In the databaseفي قاعدة البيانات

In SQL a flat file is a single CREATE TABLE, and every fact the department knows about a book or its author goes into it. The lines of the file become rows of book_list.

في SQL يصبح الملف المسطّح جملة CREATE TABLE واحدة، وكل حقيقة يعرفها القسم عن كتاب أو عن مؤلفه تدخل فيها. وتصبح أسطر الملف صفوفًا في book_list.

CREATE TABLE book_list (
  author_id   VARCHAR(6),
  author_name VARCHAR(40),
  title       VARCHAR(60)
);

The file above has four lines. How many records does it hold, and how many different authors?

في الملف أعلاه أربعة أسطر. كم سجلًّا يحمل، وكم مؤلفًا مختلفًا؟

Each line is one record, so there are four. But AD0003 appears on two of them: three authors, one of them written down twice. Keep that gap between "records" and "authors" in mind — it is the whole lesson.

كل سطر سجلّ واحد، فهي أربعة. لكن AD0003 يظهر في سطرين منها: ثلاثة مؤلفين، أحدهم مكتوب مرّتين. تذكّر هذه الفجوة بين «السجلّات» و«المؤلفين» — فهي الدرس كلّه.

2 · Its honest advantages٢ · مزاياه الحقيقية

It is tempting to call the flat file "wrong" and move on. But many small businesses and home users run on one, and are happy. If it were simply wrong, they would not.

من المغري أن نصف الملف المسطّح بأنه «خطأ» ونمضي. لكنّ كثيرًا من المشاريع الصغيرة والمستخدمين في البيوت يعملون به وهم راضون. لو كان خطأً ببساطة لما فعلوا.

A flat file is simpler and less expensive to use, and it fits the needs of many small businesses and home users. Here is what it really gives you:

الملف المسطّح أبسط وأقلّ كلفة في الاستعمال، ويناسب حاجات كثير من المشاريع الصغيرة والمستخدمين في البيوت. وهذا ما يقدّمه لك فعلًا:

AdvantageالميزةIn the book listفي قائمة الكتب
Easy to understandسهل الفهمAnyone can read the four rowsيستطيع أيّ أحد قراءة الصفوف الأربعة

Easy to extract informationسهولة استخراج المعلوماتThe title and its author are already on one lineالعنوان ومؤلفه على سطر واحد أصلًا

In the databaseفي قاعدة البيانات

"Easy to extract" is literal: every report is one SELECT on one table, with no join. Run it and change the ORDER BY — sorting the whole library is one word.

«سهولة الاستخراج» حرفيّة: كل تقرير SELECT واحدة على جدول واحد، دون أي ربط. شغّلها وغيّر ORDER BY — فرز المكتبة كلّها كلمة واحدة.

Where it stops being enoughحيث يتوقّف عن الكفاية

The limits all come from one fact: the flat file holds all data in one table. The slide lists five disadvantages: less security, data inconsistency, data redundancy, cumbersome sharing of information, and slowness on huge databases.

كل الحدود تأتي من حقيقة واحدة: الملف المسطّح يحمل كل البيانات في جدول واحد. وتعدّد الشريحة خمسة عيوب: أمان أقلّ، وعدم اتّساق البيانات، وتكرار البيانات، وصعوبة مشاركة المعلومات، والبطء في قواعد البيانات الضخمة.

The lecturer's notes add more: no multi-user access, no backup and recovery, no protection when two people change the data at once, limited functionality, and only small databases.

وتضيف ملاحظات المحاضِرة المزيد: لا وصول متعدّد المستخدمين (Multi-user Access)، ولا نسخ احتياطي واسترجاع، ولا حماية حين يغيّر شخصان البيانات في الوقت نفسه، ووظائف محدودة، وقواعد بيانات صغيرة فقط.

Definition. Multi-user access means several people can read and change the same data at the same time without spoiling each other's work.

تعريف. الوصول متعدّد المستخدمين يعني أن يستطيع عدّة أشخاص قراءة البيانات نفسها وتغييرها في الوقت نفسه دون أن يُفسد أحدهم عمل الآخر.

Which of these is a real advantage of a flat file?

أيّ هذه ميزة حقيقية للملف المسطّح؟

A spreadsheet or a text file is enough to run one. The other two are exactly what it cannot do: it repeats names (redundancy), and it has no multi-user access.

يكفي جدول بيانات أو ملف نصّي لتشغيله. أمّا الخياران الآخران فهما بالضبط ما لا يستطيعه: فهو يكرّر الأسماء (تكرار البيانات)، وليس فيه وصول متعدّد المستخدمين.

3 · The repetition it forces٣ · التكرار الذي يفرضه

Oliver Goldsmith wrote two of the department's books. The flat file has no place to write "Goldsmith" once, so it writes him into both rows. A third book would make it three.

كتب Oliver Goldsmith كتابين من كتب القسم. ليس في الملف المسطّح مكان لكتابة «Goldsmith» مرّة واحدة، فيكتبه في الصفّين كليهما. وكتاب ثالث سيجعلها ثلاث مرّات.

This is not carelessness. Each row is about one book, so anything true of the author must be copied into every one of his books' rows. The table's shape forces the copy.

ليس هذا إهمالًا. كل صفّ يتحدّث عن كتاب واحد، فأيّ شيء صحيح عن المؤلف يجب أن يُنسخ في كل صفّ من صفوف كتبه. شكل الجدول هو الذي يفرض النسخ.

Definition. Data redundancy is the same piece of information stored in more than one place.

تعريف. تكرار البيانات (Data Redundancy) هو تخزين المعلومة نفسها في أكثر من مكان.

In the databaseفي قاعدة البيانات

Count the copies. Grouping by author shows how many rows carry each name. Any number above 1 is a fact stored more than once.

عُدّ النسخ. التجميع حسب المؤلف يُظهر كم صفًّا يحمل كل اسم. وأيّ رقم أكبر من 1 حقيقة مخزّنة أكثر من مرّة.

author_idauthor_namecopies
AD0001Oscar Wilde1
AD0002Leo Tolstoy1
AD0003Oliver Goldsmith2

The library buys 28 more Goldsmith titles. How many rows of BOOK_LIST now store the name "Oliver Goldsmith"?

اشترت المكتبة 28 عنوانًا آخر لـ Goldsmith. كم صفًّا في BOOK_LIST يخزّن الآن الاسم «Oliver Goldsmith»؟

Two rows already, plus one per new book: 30. The redundancy grows with every book the author writes — and every copy is a place where the name can go wrong.

صفّان موجودان أصلًا، وصفّ لكل كتاب جديد: 30. يكبر التكرار مع كل كتاب يكتبه المؤلف — وكل نسخة مكان يمكن أن يُخطأ فيه الاسم.

4 · The update anomaly٤ · شذوذ التحديث

The library decides to catalogue authors surname first: "Goldsmith, Oliver". A librarian opens the record for Citizen of the World and fixes the name. Ask the table now: what is the name of author AD0003?

قرّرت المكتبة فهرسة المؤلفين باسم العائلة أولًا: «Goldsmith, Oliver». فتح أمين المكتبة سجلّ Citizen of the World وعدّل الاسم. اسأل الجدول الآن: ما اسم المؤلف AD0003؟

Definition. An anomaly is a change to the data — an update, an insert or a delete — that a badly shaped table turns into a wrong result.

تعريف. الشذوذ (Anomaly) تغيير في البيانات — تحديث أو إضافة أو حذف — يحوّله جدولٌ سيّئ الشكل إلى نتيجة خاطئة.

Definition. An update anomaly happens when a fact stored in several rows is changed in some of them but not all.

تعريف. شذوذ التحديث (Update Anomaly) يقع حين تُغيَّر حقيقة مخزّنة في عدّة صفوف في بعضها دون بعض.

From repetition to inconsistencyمن التكرار إلى عدم الاتّساق

The lecturer's notes put it in one line: if the same information is stored in more than one place, any change must be made everywhere it is stored. Miss one place and the table contradicts itself.

تقولها ملاحظات المحاضِرة في سطر واحد: إذا خُزّنت المعلومة نفسها في أكثر من مكان، فيجب أن يُجرى أيّ تغيير في كل مكان خُزّنت فيه. أغفِل مكانًا واحدًا فيناقض الجدول نفسه.

Definition. Data inconsistency is two stored copies of the same fact that disagree.

تعريف. عدم اتّساق البيانات (Data Inconsistency) هو أن تختلف نسختان مخزّنتان من الحقيقة نفسها.

In the databaseفي قاعدة البيانات

The librarian's UPDATE chose the row by title, so it reached one copy. SQL ran it without a word of complaint. Run it and read AD0003's rows:

اختارت جملة UPDATE التي كتبها الأمين الصفَّ بالعنوان، فوصلت إلى نسخة واحدة. ونفّذتها SQL دون أيّ اعتراض. شغّلها واقرأ صفوف AD0003:

author_idauthor_nametitle
AD0003Goldsmith, OliverCitizen of the World
AD0003Oliver GoldsmithAndrocles and the Lion

Writing WHERE author_id = 'AD0003' would have caught both rows this time. But that is a rule the person must remember on every change; the table itself still allows two names.

لو كُتب WHERE author_id = 'AD0003' لالتقط الصفّين هذه المرّة. لكنّ هذه قاعدة على الشخص أن يتذكّرها عند كل تغيير؛ أمّا الجدول نفسه فما زال يسمح باسمين.

After the update, a report lists books by author name. Under how many different authors does Goldsmith's work appear?

بعد التعديل، يعرض تقرير الكتب حسب اسم المؤلف. تحت كم مؤلفًا مختلفًا تظهر أعمال Goldsmith؟

A report by name sees two different strings, so it shows one author as two. That is the inconsistency the update anomaly leaves behind: the data is now wrong, and nobody was warned.

التقرير حسب الاسم يرى نصّين مختلفين، فيعرض المؤلف الواحد مؤلفَين. هذا هو عدم الاتّساق الذي يتركه شذوذ التحديث: البيانات صارت خاطئة، ولم يُنبَّه أحد.

5 · The insert anomaly٥ · شذوذ الإضافة

The library has ordered its first Jane Austen book. It wants to record the author now, as AD0004, so the order can refer to her. The book has not arrived. Where in BOOK_LIST does she go?

طلبت المكتبة أوّل كتاب لـ Jane Austen، وتريد تسجيل المؤلفة الآن برقم AD0004 ليشير إليها الطلب. لم يصل الكتاب بعد. أين تُوضع في BOOK_LIST؟

Every row of BOOK_LIST is a book. An author can only enter the table riding on one of their books. With no book, there is no honest row to write.

كل صفّ في BOOK_LIST كتاب. ولا يدخل المؤلف الجدولَ إلا محمولًا على أحد كتبه. فإن لم يكن هناك كتاب، فلا صفّ صادقًا يُكتب.

Definition. An insert anomaly happens when you cannot record one fact without also recording another, unrelated one.

تعريف. شذوذ الإضافة (Insert Anomaly) يقع حين لا تستطيع تسجيل حقيقة دون أن تسجّل معها حقيقة أخرى لا علاقة لها بها.

Defect: Jane Austen cannot be recorded at all. The only kind of row the table has is "a book and its author", and there is no book yet.

العيب: لا يمكن تسجيل Jane Austen أصلًا. فالنوع الوحيد من الصفوف في الجدول هو «كتاب ومؤلفه»، ولا كتاب بعد.

She is in — but row 5 claims to be a book and is not. Count the rows and you get five books for a library that owns four. When her book arrives, she will be stored twice.

دخلت المؤلفة — لكنّ الصفّ 5 يدّعي أنه كتاب وهو ليس كذلك. عُدّ الصفوف تجد خمسة كتب لمكتبة تملك أربعة. وحين يصل كتابها ستُخزَّن مرّتين.

Fixed: AUTHOR lists authors, BOOK lists books. Jane Austen is one row in AUTHOR, with no book needed, and BOOK still has exactly four rows.

أُصلح: AUTHOR يسرد المؤلفين، وBOOK يسرد الكتب. Jane Austen صفّ واحد في AUTHOR دون حاجة إلى كتاب، وما زال في BOOK أربعة صفوف بالضبط.

In the databaseفي قاعدة البيانات

Version 2 in SQL is an INSERT with an empty title. It succeeds — and then every count of books is wrong:

النسخة 2 في SQL جملة INSERT بعنوان فارغ. تنجح — ثم يصبح كل عدّ للكتب خاطئًا:

INSERT INTO book_list VALUES ('AD0004', 'Jane Austen', NULL);

SELECT COUNT(*) AS book_rows FROM book_list;
book_rows
5

In version 3 the same author is INSERT INTO authors, and SELECT COUNT(*) FROM books still returns 4.

في النسخة 3 تصبح المؤلفة نفسها INSERT INTO authors، ويبقى SELECT COUNT(*) FROM books يُرجع 4.

Which version of the evolve block above records Jane Austen and keeps the book count right?

أيّ نسخة في المراحل أعلاه تسجّل Jane Austen وتُبقي عدد الكتب صحيحًا؟

Version 1 cannot record her; version 2 records her as a fake book. Only version 3 gives the author a row that is about an author, so the books table stays a list of books.

النسخة 1 لا تستطيع تسجيلها، والنسخة 2 تسجّلها كتابًا مزيّفًا. النسخة 3 وحدها تعطي المؤلفة صفًّا يتحدّث عن مؤلف، فيبقى جدول الكتب قائمةَ كتب.

6 · The delete anomaly٦ · شذوذ الحذف

The department's only copy of War and Peace is lost, so its row is deleted. A week later someone asks: "What was Tolstoy's author code?" The table has no idea.

ضاعت نسخة القسم الوحيدة من War and Peace، فحُذف صفّها. وبعد أسبوع سأل أحدهم: «ما رمز المؤلف Tolstoy؟» ولا علم للجدول بذلك.

Definition. A delete anomaly happens when deleting one fact also destroys another fact you wanted to keep.

تعريف. شذوذ الحذف (Delete Anomaly) يقع حين يُتلف حذفُ حقيقة حقيقةً أخرى أردت الاحتفاظ بها.

In the databaseفي قاعدة البيانات

Delete the book, then look for the author. Zero rows: AD0002 is gone from the database.

احذف الكتاب، ثم ابحث عن المؤلف. صفر صفوف: اختفى AD0002 من قاعدة البيانات.

With separate tables, the same DELETE FROM books WHERE title = 'War and Peace' leaves authors untouched: the author row AD0002, Leo Tolstoy is still there.

ومع جداول منفصلة، تترك الجملة نفسها DELETE FROM books WHERE title = 'War and Peace' جدولَ authors كما هو: صفّ المؤلف AD0002, Leo Tolstoy ما زال موجودًا.

Which deletion from the original four-row BOOK_LIST does not lose an author?

أيّ حذف من BOOK_LIST الأصلي ذي الصفوف الأربعة لا يُضيع مؤلفًا؟

Goldsmith has a second row, so he survives. Wilde and Tolstoy each have one row, so deleting their book deletes them. Notice the irony: the repetition that causes the update anomaly is the only thing protecting Goldsmith here.

لـ Goldsmith صفّ ثانٍ فيبقى. أمّا Wilde وTolstoy فلكلّ منهما صفّ واحد، فحذف كتابه يحذفه. لاحظ المفارقة: التكرار الذي يسبّب شذوذ التحديث هو الشيء الوحيد الذي يحمي Goldsmith هنا.

7 · One fact, one place٧ · حقيقة واحدة، مكان واحد

Three anomalies, three symptoms. Patching each one separately — careful WHERE clauses, fake rows, "never delete the last book" — only moves the risk onto the people using the table. What is the one cause?

ثلاثة أنواع من الشذوذ، وثلاثة أعراض. ترقيع كلّ منها وحده — شروط WHERE حذرة، وصفوف مزيّفة، و«لا تحذف آخر كتاب أبدًا» — لا يفعل إلا أن ينقل الخطر إلى من يستعملون الجدول. فما السبب الواحد؟

One table is describing two different things — books and authors. Give each its own table, store each fact once, and connect them through a common field, AUTHOR_ID. Lesson 2 makes that connection precise.

جدول واحد يصف شيئين مختلفين — الكتب والمؤلفين. أعطِ كلًّا منهما جدوله، وخزّن كل حقيقة مرّة واحدة، واربط بينهما بحقل مشترك، AUTHOR_ID. والدرس 2 يجعل هذا الربط دقيقًا.

Defect: the author's name is stored once per book. Renaming an author means changing every one of those rows — the update anomaly.

العيب: اسم المؤلف مخزّن مرّة لكل كتاب. وتغيير اسم مؤلف يعني تعديل كل واحد من تلك الصفوف — شذوذ التحديث.

Fixed: the name lives in one row of AUTHOR, so a rename is one change. A book only carries AUTHOR_ID. Adding an author without a book, or deleting a book, no longer touches anything else.

أُصلح: يعيش الاسم في صفّ واحد من AUTHOR، فتغييره تعديل واحد. ولا يحمل الكتاب إلا AUTHOR_ID. وإضافة مؤلف بلا كتاب، أو حذف كتاب، لم تعد تمسّ شيئًا آخر.

What a multi-table database buysما الذي تكسبه قاعدة البيانات متعدّدة الجداول

The lecturer lists five advantages of a relational, multiple-table database. Each one answers a problem from this lesson:

تعدّد المحاضِرة خمس مزايا لقاعدة البيانات العلائقية متعدّدة الجداول. وكلّ منها يجيب عن مشكلة من هذا الدرس:

Which advantage of a multi-table database directly prevents the update anomaly?

أيّ ميزة لقاعدة البيانات متعدّدة الجداول تمنع شذوذ التحديث مباشرة؟

With the name in one place, there is no second copy to forget, so the data cannot contradict itself. "Less hardware and software" is an advantage of the flat file, not of the multi-table design.

حين يكون الاسم في مكان واحد، لا توجد نسخة ثانية تُنسى، فلا تستطيع البيانات أن تناقض نفسها. أمّا «عتاد وبرمجيات أقلّ» فميزة للملف المسطّح، لا للتصميم متعدّد الجداول.

True or false: splitting BOOK_LIST into AUTHOR and BOOK removes all three anomalies at once.

صح أم خطأ: تقسيم BOOK_LIST إلى AUTHOR وBOOK يزيل أنواع الشذوذ الثلاثة دفعة واحدة.

True. All three had one cause: author facts lived inside book rows. Once authors have their own rows, a rename is one change, a new author needs no book, and deleting a book leaves its author alone.

صح. للثلاثة سبب واحد: حقائق المؤلف كانت تعيش داخل صفوف الكتب. وحين يصبح للمؤلفين صفوفهم، يصير تغيير الاسم تعديلًا واحدًا، ولا يحتاج المؤلف الجديد إلى كتاب، ويترك حذفُ كتاب مؤلفَه كما هو.

(a) A flat file is a sound choice: small, one user, and it is easy, cheap and needs little software. (b) It is not: a flat file has no multi-user access, no protection when two people change data at once, and no backup and recovery.

(أ) الملف المسطّح خيار سليم: بيانات صغيرة ومستخدم واحد، وهو سهل ورخيص ويحتاج إلى برمجيات قليلة. (ب) ليس كذلك: فالملف المسطّح لا وصول متعدّد المستخدمين فيه، ولا حماية حين يغيّر شخصان البيانات معًا، ولا نسخ احتياطي واسترجاع.

Key takeawaysالخلاصة

  • A flat file stores all data in one table, usually as plain text with one record per line.
  • الملف المسطّح يحفظ كل البيانات في جدول واحد، غالبًا نصًّا عاديًّا بسجلّ واحد في كل سطر.
  • Its advantages are real: easy, cheap, one place, simple sorting. They fit small, single-user needs.
  • مزاياه حقيقية: سهل، ورخيص، ومكان واحد، وفرز بسيط. وهي تناسب الحاجات الصغيرة لمستخدم واحد.
  • One table describing two things forces redundancy; redundancy makes inconsistency possible.
  • الجدول الواحد الذي يصف شيئين يفرض التكرار، والتكرار يجعل عدم الاتّساق ممكنًا.
  • Update anomaly: some copies changed, not all. Insert anomaly: no row for a fact on its own. Delete anomaly: one deletion destroys another fact.
  • شذوذ التحديث: تغيّرت بعض النسخ لا كلّها. شذوذ الإضافة: لا صفّ لحقيقة وحدها. شذوذ الحذف: حذف واحد يُتلف حقيقة أخرى.
  • The cure for all three is one fact, one place: a table per thing, connected by a common field.
  • علاج الثلاثة واحد: حقيقة واحدة في مكان واحد — جدول لكل شيء، يربط بينها حقل مشترك.

Mistakes to avoidأخطاء يجب تجنّبها

  • Calling a flat file "always wrong" — for a small, single-user list it is the sensible choice.
  • وصف الملف المسطّح بأنه «خطأ دائمًا» — فهو الخيار المعقول لقائمة صغيرة يستعملها شخص واحد.
  • Counting rows as things: four rows of BOOK_LIST are four books, not four authors.
  • عدّ الصفوف على أنها أشياء: الصفوف الأربعة في BOOK_LIST أربعة كتب، لا أربعة مؤلفين.
  • Fixing an anomaly with a habit ("always update by ID") instead of with the table's shape.
  • إصلاح الشذوذ بعادة («حدّث دائمًا بالرقم») بدل إصلاحه بشكل الجدول.
  • Inventing a fake row (an author with an empty title) to get around an insert anomaly.
  • اختلاق صفّ مزيّف (مؤلف بعنوان فارغ) للالتفاف على شذوذ الإضافة.
