1 · The diagram, and the rules it carries١ · المخطّط، والقواعد التي يحملها

A diagram cannot stop anyone typing a book with no title, or two authors with the same id. Only the table can. Every mark Matt drew is a rule the table must enforce — if you forget to write it down, the database never hears about it.

لا يستطيع المخطّط أن يمنع أحدًا من إدخال كتاب بلا عنوان، أو مؤلّفَين بالمعرّف نفسه. الجدول وحده يستطيع. كل علامة رسمها مات قاعدةٌ على الجدول أن يفرضها — وإن نسيتَ أن تكتبها، فلن تسمع بها قاعدة البيانات أبدًا.

Lesson 3 gave the steps: entities become tables, attributes become columns, relationships become foreign keys. The marks beside each attribute decide the constraints:

أعطى الدرس 3 الخطوات: الكيانات تصير جداول، والخصائص تصير أعمدة، والعلاقات تصير مفاتيح أجنبية. أمّا العلامات بجانب كل خاصية فتقرّر القيود:

In MEMBER, which line becomes a column the database lets you leave empty?

2 · AUTHOR becomes authors٢ · AUTHOR يصير authors

The rule: each AUTHOR is identified by its Id, and must have a Name.

القاعدة: كل AUTHOR يُعرَّف بمعرّفه Id، ويجب أن يكون له Name.

Step 2a · Write the tableالخطوة 2أ · اكتب الجدول

Create authors with columns id (NUMBER) and name (VARCHAR2(30)), and the two constraints the marks ask for. The check reads your table's columns, its primary key and its NOT NULL columns.

أنشئ الجدول authors بعمودين id (NUMBER) وname (VARCHAR2(30))، والقيدين اللذين تطلبهما العلامتان. يقرأ التصحيح أعمدة جدولك، ومفتاحه الأساسي، وأعمدته التي عليها NOT NULL.

Show the answerاعرض الجواب 
CREATE TABLE authors (
  id   NUMBER       PRIMARY KEY,
  name VARCHAR2(30) NOT NULL
);

Leave out NOT NULL and the check fails: the table would run, but nothing would stop an author with no name. A primary key needs no NOT NULL of its own — in Oracle a primary key is never null.

احذف NOT NULL فيفشل التصحيح: سيعمل الجدول، لكن لا شيء سيمنع مؤلّفًا بلا اسم. ولا يحتاج المفتاح الأساسي إلى NOT NULL خاصّ به — ففي Oracle لا يكون المفتاح الأساسي null أبدًا.

Now test the rule. This box starts with authors built and two rows in it, Oscar Wilde (1) and Leo Tolstoy (2). Run it:

والآن اختبر القاعدة. يبدأ هذا الصندوق والجدول authors مبنيّ وفيه صفّان، Oscar Wilde (1) وLeo Tolstoy (2). شغّله:

Cannot insert record, because it already exists in primary key index

Id 2 is taken, so the row is refused and the table keeps its two authors. Change 2 to 3 and run again: Oliver Goldsmith goes in. Then try INSERT INTO authors (id) VALUES (4); — it fails with Wrong NULL value in NOT NULL column name.

المعرّف 2 مأخوذ، فيُرفض الصفّ ويحتفظ الجدول بمؤلّفَيه. غيّر 2 إلى 3 وشغّل من جديد: يدخل Oliver Goldsmith. ثم جرّب INSERT INTO authors (id) VALUES (4); — فتفشل برسالة Wrong NULL value in NOT NULL column name.

Which mark on the diagram refused INSERT INTO authors (id) VALUES (4);?

أيّ علامة في المخطّط رفضت INSERT INTO authors (id) VALUES (4);؟

Id 4 is new, so the key is happy. The row has no name, and * — written as NOT NULL — says every author must have one.

المعرّف 4 جديد، فلا اعتراض من المفتاح. لكن الصفّ بلا اسم، و* — المكتوبة NOT NULL — تقول إن لكل مؤلّف اسمًا.

One honest gap in this browser engine: it accepts an explicit NULL in a NUMBER column even when it is the primary key or declared NOT NULL. Oracle refuses both. So this lab tests the * rule on text columns, where the engine is strict.

ثغرة نعترف بها في محرّك المتصفّح هذا: يقبل NULL صريحة في عمود NUMBER حتى لو كان مفتاحًا أساسيًّا أو معلنًا NOT NULL. أمّا Oracle فيرفض الحالتين. لذلك يختبر هذا المختبر قاعدة * على الأعمدة النصّية، حيث المحرّك صارم.

3 · BOOK becomes books٣ · BOOK يصير books

The faculty member wants each title catalogued once. Title is not the UID — Id is — yet two books with the same title would be a mistake. Matt marked it U.

يريد عضو هيئة التدريس أن يُفهرَس كل عنوان مرّة واحدة. Title ليس المعرّف الفريد — فالمعرّف هو Id — ومع ذلك فإن كتابين بالعنوان نفسه خطأ. فوسمه مات بعلامة U.

The rule: each BOOK is identified by its Id, must have a Title, and no two books share a title.

القاعدة: كل BOOK يُعرَّف بمعرّفه Id، ويجب أن يكون له Title، ولا يشترك كتابان في عنوان واحد.

Step 3a · Write the tableالخطوة 3أ · اكتب الجدول

Create books with id (VARCHAR2(15)) and title (VARCHAR2(50)). Three constraints in all: one for #, two for U *.

أنشئ الجدول books بالعمودين id (VARCHAR2(15)) وtitle (VARCHAR2(50)). ثلاثة قيود في المجموع: واحد لـ #، واثنان لـ U *.

Show the answerاعرض الجواب 
CREATE TABLE books (
  id    VARCHAR2(15) PRIMARY KEY,
  title VARCHAR2(50) NOT NULL UNIQUE
);

Oracle's physical model on slide 27 names the same constraint BOOKS_Title_UK. Writing it as CONSTRAINT books_title_uk UNIQUE (title) at the end of the column list passes the check too.

يسمّي النموذج الفيزيائي في الشريحة 27 القيدَ نفسه BOOKS_Title_UK. وكتابته على شكل CONSTRAINT books_title_uk UNIQUE (title) في آخر قائمة الأعمدة تجتاز التصحيح أيضًا.

This box starts with three books: A Vision, War and Peace and Citizen of the World. Try to catalogue War and Peace a second time:

يبدأ هذا الصندوق بثلاثة كتب: A Vision وWar and Peace وCitizen of the World. حاول فهرسة War and Peace مرّة ثانية:

Cannot insert record, because it already exists in unique index

The id BK004 is new, so the primary key has no complaint — the unique key does. Change the title to 'Androcles and the Lion' and run again: the table now holds four books.

المعرّف BK004 جديد، فلا اعتراض للمفتاح الأساسي — الاعتراض من المفتاح الفريد. غيّر العنوان إلى 'Androcles and the Lion' وشغّل من جديد: صار في الجدول أربعة كتب.

Both # and U forbid duplicates. What does # give Id that U does not give Title?

كلٌّ من # وU يمنع التكرار. فما الذي تعطيه # للعمود Id ولا تعطيه U للعمود Title؟

A table has one primary key, and it is what a foreign key refers to: a BOOK TRANSACTION will record BOOKS_Id, not the title. U only promises no repeats.

للجدول مفتاح أساسي واحد، وهو ما يشير إليه المفتاح الأجنبي: فـ BOOK TRANSACTION ستسجّل BOOKS_Id لا العنوان. أمّا U فلا تعد إلا بعدم التكرار.

4 · MEMBER becomes members٤ · MEMBER يصير members

The library posts reminder letters, so it needs a full address for every member. But not every address has a state. The model has to say both things at once — and so does the table.

ترسل المكتبة رسائل تذكير بالبريد، فهي تحتاج إلى عنوان كامل لكل عضو. لكن ليس لكل عنوان ولاية. على النموذج أن يقول الأمرين معًا — وكذلك الجدول.

The rule: each MEMBER is identified by its Id, must have a first name, last name, street address, city and ZIP, and may have a state.

القاعدة: كل MEMBER يُعرَّف بمعرّفه Id، ويجب أن يكون له اسم أوّل واسم عائلة وعنوان شارع ومدينة ورمز بريدي، ويجوز أن تكون له ولاية.

Step 4a · Write the tableالخطوة 4أ · اكتب الجدول

Create members with id (NUMBER), first_name, last_name, city, state (all VARCHAR2(20)), street_address (VARCHAR2(40)) and zip (VARCHAR2(10)). The check fails a missing NOT NULL — and an extra one.

أنشئ الجدول members بالأعمدة id (NUMBER)، وfirst_name وlast_name وcity وstate (كلها VARCHAR2(20))، وstreet_address (VARCHAR2(40))، وzip (VARCHAR2(10)). يُفشِل التصحيح قيد NOT NULL ناقصًا — وقيدًا زائدًا كذلك.

Show the answerاعرض الجواب 
CREATE TABLE members (
  id             NUMBER       PRIMARY KEY,
  first_name     VARCHAR2(20) NOT NULL,
  last_name      VARCHAR2(20) NOT NULL,
  street_address VARCHAR2(40) NOT NULL,
  city           VARCHAR2(20) NOT NULL,
  state          VARCHAR2(20),
  zip            VARCHAR2(10) NOT NULL
);

NOT NULL on state is the extra one: it would turn away every member whose address has no state, which the o on the diagram allows.

قيد NOT NULL على state هو القيد الزائد: سيرفض كل عضو ليس في عنوانه ولاية، وهو ما تسمح به o في المخطّط.

Sara and Omar from Lesson 5 are already in this box. A clerk adds Lina but forgets her city:

Sara وOmar من الدرس 5 موجودان في هذا الصندوق. يضيف موظّف Lina لكنه ينسى مدينتها:

Wrong NULL value in NOT NULL column city

The column list leaves out state as well, and the database says nothing about it. Only the missing city is refused, because only City was marked *.

قائمة الأعمدة تُسقِط state أيضًا، ولا تقول قاعدة البيانات عنه شيئًا. لا يُرفض إلا غياب city، لأن City وحدها وُسِمت بـ *.

The clerk's INSERT left out two columns. Why was only one of them refused?

أسقطت جملة INSERT التي كتبها الموظّف عمودين. لماذا رُفض أحدهما فقط؟

A column you leave out of an INSERT becomes null. Null is fine in state, which is optional, and refused in city, which is mandatory. The table is repeating the diagram.

العمود الذي تُسقطه من INSERT يصير null. والقيمة null مقبولة في state لأنه اختياري، ومرفوضة في city لأنه إلزامي. الجدول يكرّر ما قاله المخطّط.

Thread · the SQL trackخيط · مسار SQL

SQL Chapter 1 — First Steps writes CREATE TABLE with a PRIMARY KEY, and Chapter 2 — Multiple Columns gives each column a type. Neither ever writes NOT NULL, because neither has a model to ask. This lab is that question: the * and o on the diagram decide it, column by column.

يكتب الفصل 1 من مسار SQL — الخطوات الأولى جملة CREATE TABLE مع PRIMARY KEY، ويعطي الفصل 2 — أعمدة متعدّدة كل عمود نوعًا. ولا يكتب أيٌّ منهما NOT NULL أبدًا، لأنه لا نموذج لديه يسأله. وهذا المختبر هو ذلك السؤال: علامتا * وo في المخطّط تحسمانه، عمودًا عمودًا.

Key takeawaysالخلاصة

  • An entity becomes a table; each attribute becomes one column with a data type.
  • الكيان يصير جدولًا، وكل خاصية تصير عمودًا واحدًا بنوع بيانات.
  • # becomes PRIMARY KEY, * becomes NOT NULL, U becomes UNIQUE, and o adds nothing.
  • # تصير PRIMARY KEY، و* تصير NOT NULL، وU تصير UNIQUE، وo لا تضيف شيئًا.
  • A rule you do not write as a constraint is not enforced: the diagram cannot refuse a row, only the table can.
  • القاعدة التي لا تكتبها قيدًا لا تُفرَض: المخطّط لا يستطيع أن يرفض صفًّا، الجدول وحده يستطيع.
  • Relationships are not built yet, so these tables cannot say who wrote or published a book.
  • العلاقات لم تُبنَ بعد، فلا تستطيع هذه الجداول أن تقول من كتب الكتاب أو من نشره.

Mistakes to avoidأخطاء يجب تجنّبها

  • Forgetting NOT NULL on a * attribute — the table runs, and silently accepts empty rows.
  • نسيان NOT NULL على خاصية * — يعمل الجدول، ويقبل الصفوف الفارغة بصمت.
  • Adding NOT NULL to an o attribute — the table turns away rows the business allows.
  • إضافة NOT NULL إلى خاصية o — فيرفض الجدول صفوفًا يسمح بها العمل.
  • Making the U attribute the primary key instead of the # one.
  • جعل الخاصية ذات U مفتاحًا أساسيًّا بدلًا من الخاصية ذات #.
  • Faking a missing optional value with a space or 'none' instead of leaving it null.
  • تزييف القيمة الاختيارية الغائبة بمسافة أو بـ 'none' بدلًا من تركها null.
