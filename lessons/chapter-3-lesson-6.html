Lesson 6 — Changing Relationships

الدرس ٦ — تغيير العلاقات

A relationship isn't permanent either. Re-pointing a child row at a different parent is just an ordinary UPDATE on its foreign-key column — the same skills from chapters 1 and 2.

العلاقة ليست دائمة كذلك. إعادة توجيه صف ابن إلى أبٍ مختلف ما هي إلا عبارة UPDATE عادية على عمود المفتاح الأجنبي — المهارات نفسها من الفصلين الأول والثاني.

Removing the relationship entirely means dropping the foreign-key column itself with ALTER TABLE ... DROP COLUMN. After that, there's no way left to tell which parent a row used to belong to — so treat it with the same care as any other DROP COLUMN.

أما إزالة العلاقة كليًّا فتعني حذف عمود المفتاح الأجنبي نفسه بـALTER TABLE ... DROP COLUMN. وبعد ذلك لا تبقى وسيلة لمعرفة الأب الذي كان الصف ينتمي إليه — فتعامل معها بالحذر نفسه المتّبع مع أي DROP COLUMN.

Syntax pattern
نمط الصياغة
UPDATE child_table SET parent_id_col = <different parent id> WHERE id = <child id>;   -- re-point
ALTER TABLE child_table DROP COLUMN parent_id_col;                              -- remove entirely

Worked examples — books and authors

أمثلة محلولة — books وauthors

Example 1 — re-point a book, confirmed via JOINمثال ١ — إعادة توجيه كتاب، مؤكَّدة عبر JOIN
Example 2 — an unset foreign key reads as NULLمثال ٢ — مفتاح أجنبي غير مضبوط يُقرأ NULL

A foreign key with no value yet (or no longer pointing anywhere) is simply NULL — "no relationship set", not a broken one.

المفتاح الأجنبي الذي لا قيمة له بعد (أو لم يعد يشير إلى أي شيء) هو ببساطة NULL — "لا علاقة مضبوطة"، لا علاقة معطوبة.

Example 3 — remove the relationship entirelyمثال ٣ — إزالة العلاقة كليًّا

This is the full removal — after this, there is no link left between books and authors until the column is added back.

هذه هي الإزالة الكاملة — بعدها لا تبقى أي صلة بين books وauthors حتى يُعاد إضافة العمود.
