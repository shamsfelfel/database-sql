Lesson 1 — From Filters to Subqueries

الدرس ١ — من التصفية إلى الاستعلامات الفرعية

Every filter so far compared a column to something already known — a literal (Chapter 1) or a joined row (Chapter 3).

كل تصفية حتى الآن كانت تقارن عمودًا بشيء معروف مسبقًا — قيمة حرفية (الفصل ١) أو صف مضموم من جدول آخر (الفصل ٣).

A subquery lets the comparison value be computed by another query: a SELECT nested in parentheses, used where a value would go. It runs first, returns a value, and that value takes the literal's place.

يتيح الاستعلام الفرعي أن تكون قيمة المقارنة محسوبة باستعلام آخر: جملة SELECT مُضمَّنة بين قوسين، تُوضَع حيث تُوضَع القيمة. يُنفَّذ أولًا فيُرجع قيمة، وتحل تلك القيمة محل القيمة الحرفية.

Syntax pattern
نمط الصياغة
SELECT title, price
FROM books
WHERE price > (SELECT AVG(price) FROM books);

Worked examples — books and authors

أمثلة محلولة — books وauthors

Example 1 — a literal guessمثال ١ — تخمين بقيمة حرفية
25.00 is a guess — what we really want is "above average".25.00 مجرد تخمين — وما نريده فعلًا هو "أعلى من المتوسط".
Example 2 — a JOIN compares to a rowمثال ٢ — الضم يقارن بصفٍّ آخر
A JOIN handles "a row in another table", not "a computed number".يعالج JOIN حالة "صف في جدول آخر"، لا حالة "رقم محسوب".
Example 3 — compare to a computed valueمثال ٣ — المقارنة بقيمة محسوبة
The parenthesized SELECT runs first and its number replaces the literal.تُنفَّذ جملة SELECT الموجودة بين القوسين أولًا، فيحل الرقم الناتج عنها محل القيمة الحرفية.
