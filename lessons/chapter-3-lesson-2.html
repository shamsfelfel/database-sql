Lesson 2 — Inserting with a Key

الدرس ٢ — الإدراج بمفتاح

Once a foreign-key column exists, inserting a new child row is exactly like any other INSERT (chapter 1) — you just include a value for the foreign-key column, and that value should be the id of an existing parent row. Order doesn't matter for the insert itself, but the relationship only makes sense if the parent row already exists.

بمجرد وجود عمود المفتاح الأجنبي، يصبح إدراج صف ابن جديد تمامًا مثل أي INSERT آخر (الفصل الأول) — تكتفي بتضمين قيمة لعمود المفتاح الأجنبي، وينبغي أن تكون تلك القيمة رقم id لصفٍّ أب موجود. الترتيب لا يهمّ للإدراج نفسه، لكن العلاقة لا يكون لها معنى إلا إذا كان صف الأب موجودًا بالفعل.

Syntax pattern
نمط الصياغة
INSERT INTO child_table (id, ..., parent_id_col) VALUES (..., <existing parent id>);

Worked examples — inserting books with an author_id

أمثلة محلولة — إدراج books مع author_id

The books table already carries the author_id column from lesson 1. Each new book names an existing author by their id.

يحمل جدول books عمود author_id منذ الدرس الأول. وكل كتاب جديد يذكر مؤلفًا موجودًا برقمه.

Example 1 — insert a child row referencing author 4مثال ١ — إدراج صف ابن يشير إلى المؤلف 4

This gives Daniel Kessler (author id 4) his first book.

هذا يمنح Daniel Kessler (المؤلف رقم 4) أول كتاب له.

Example 2 — confirm the referenced author existsمثال ٢ — التأكد من وجود المؤلف المُشار إليه

Author id 4 really is there — that's why pointing a book at it makes sense.

المؤلف رقم 4 موجود فعلًا — ولهذا يكون توجيه كتاب إليه ذا معنى.

Example 3 — a second book for the same authorمثال ٣ — كتاب ثانٍ للمؤلف نفسه

Two books now point at the same author — that's the "one author, many books" shape.

كتابان يشيران الآن إلى المؤلف نفسه — وهذه هي صورة "مؤلف واحد، كتب كثيرة".
