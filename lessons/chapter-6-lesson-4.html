Lesson 4 — Views over Aggregation

الدرس ٤ — العروض على التجميع

Chapter 5 turned rows into summaries: one row per genre, per category, per level. Those summaries are usually what a report wants — and a report query gets rewritten over and over. Put the GROUP BY inside a view and the summary becomes a thing with a name, shaped like a small table: one row per group, one column per measure.

حوّل الفصل الخامس الصفوف إلى ملخّصات: صفٌّ لكل نوع، أو لكل فئة، أو لكل مستوى. وهذه الملخّصات هي عادةً ما يريده التقرير — واستعلام التقرير يُعاد كتابته مرّة بعد مرّة. ضَعِ GROUP BY داخل عرض فيصبح الملخّص شيئًا له اسم، بهيئة جدول صغير: صفّ لكل مجموعة، وعمود لكل مقياس.

There is a quiet bonus here. Inside the view, COUNT(*) AS book_count is an aggregate and needs HAVING to be filtered. Outside the view, book_count is just a column — so you filter it with an ordinary WHERE, sort it, even aggregate it again.

وهناك مكافأة هادئة هنا. فداخل العرض تكون COUNT(*) AS book_count دالّة تجميعية وتحتاج HAVING لتصفيتها. أمّا خارج العرض فإن book_count مجرّد عمود — فتُصفّيه بـWHERE عاديّة، وترتّبه، بل وتُجمّعه مرّة أخرى.

Give every measure a descriptive name: book_count, avg_price, total_stock. The name is the view's interface — and unlike a bare COUNT(*), it says what the number means.

وامنح كل مقياس اسمًا واصفًا: book_count وavg_price وtotal_stock. فالاسم هو واجهة العرض — وبخلاف COUNT(*) المجرّدة، يقول ماذا يعني الرقم.

Syntax pattern
نمط الصياغة
CREATE VIEW genre_stats AS
SELECT genre,
       COUNT(*) AS book_count,
       ROUND(AVG(price), 2) AS avg_price
FROM books
GROUP BY genre;

SELECT genre, book_count FROM genre_stats WHERE book_count >= 2;
