Lesson 6 — Managing Views

الدرس ٦ — إدارة العروض

Views accumulate. Definitions change, reports get retired, and someone eventually asks the frightening question: can I delete this? With a view the answer is reassuring — DROP VIEW throws away a saved query and nothing else. Every row still sits in its table, untouched.

العروض تتراكم. فالتعريفات تتغيّر، والتقارير تُحال إلى التقاعد، ويسأل أحدهم في النهاية السؤال المخيف: هل أستطيع حذف هذا؟ ومع العرض يكون الجواب مُطمئنًا — فـDROP VIEW تتخلّص من استعلام محفوظ ولا شيء غير ذلك. وكل صفّ يبقى في جدوله كما هو.

That is the sharp line to keep in mind: DROP TABLE destroys data; DROP VIEW destroys a shortcut. Treat them with very different levels of fear.

وهذا هو الخطّ الحادّ الذي ينبغي تذكّره: DROP TABLE تُهلك بيانات؛ وDROP VIEW تُهلك اختصارًا. فتعامَل معهما بدرجتَي خوف مختلفتين جدًّا.

Changing a view is a two-step move here: DROP VIEW it, then CREATE VIEW it again with the new query. (Several database engines offer CREATE OR REPLACE VIEW as a one-liner; the engine behind this course does not, so get used to the two steps — they work everywhere.)

وتغيير العرض هنا حركة من خطوتين: DROP VIEW له، ثم CREATE VIEW من جديد بالاستعلام الجديد. (تُوفّر عدّة محرّكات قواعد بيانات الصيغة CREATE OR REPLACE VIEW في سطر واحد؛ والمحرّك الذي يقف خلف هذه الدورة لا يُوفّرها، فاعتَد الخطوتين — فهما تعملان في كل مكان.)

Two guards make scripts safe to re-run: CREATE VIEW IF NOT EXISTS creates the view only when it is missing — if it already exists, the old definition is kept and no error is raised — and DROP VIEW IF EXISTS removes it when present and stays quiet when not. Without the guards, creating a view twice is an error, and so is dropping one that was never there.

وحارسان يجعلان السكربتات آمنة لإعادة التشغيل: CREATE VIEW IF NOT EXISTS تُنشئ العرض فقط إذا كان مفقودًا — وإن كان موجودًا بقي التعريف القديم دون خطأ — وDROP VIEW IF EXISTS تحذفه إن وُجد وتسكت إن لم يوجد. ودون الحارسين يكون إنشاء العرض مرّتين خطأً، وكذلك حذف عرض لم يوجد يومًا.

Last thing to know: views depend on what they read. Drop a table or a view that another view is built on, and the view above it breaks the next time anyone reads it. Before you drop, ask what is standing on top.

وآخر ما ينبغي معرفته: العروض تعتمد على ما تقرأ منه. فإذا حذفت جدولًا أو عرضًا بُني عليه عرضٌ آخر، انكسر العرض الذي فوقه في أول قراءة تالية. فقبل الحذف اسأل: ماذا يقف فوقه؟

Syntax pattern
نمط الصياغة
DROP VIEW IF EXISTS cheap_books;

CREATE VIEW cheap_books AS
SELECT id, title, price
FROM books
WHERE price < 20;

4write statement

A view low_stock (id, name, stock_qty) already exists, and it uses the threshold stock_qty < 20. Redefine it — same name, same three columns — so the threshold becomes stock_qty < 10.

يوجد عرض low_stock (id وname وstock_qty) ويستخدم الحدّ stock_qty < 20. أعِد تعريفه — بالاسم نفسه والأعمدة الثلاثة نفسها — ليصبح الحدّ stock_qty < 10.
