Lesson 1 — Keys & Relationships

الدرس ١ — المفاتيح والعلاقات

A foreign key is a column in one table that holds the primary-key value of a row in another table — it's how one row "points to" another. When books.author_id holds the value 2, it means "this book belongs to the author whose id is 2" in the authors table. This is what lets two tables that model different things — authors, and the books they wrote — stay connected without repeating an author's whole name on every one of their books. One author can be pointed to by many books; this shape is called a one-to-many relationship.

المفتاح الأجنبي (foreign key) هو عمود في جدول يحمل قيمة المفتاح الأساسي لصفٍّ في جدول آخر — وهو الطريقة التي "يشير" بها صف إلى صف آخر. فحين يحمل books.author_id القيمة 2، فهذا يعني "هذا الكتاب يخص المؤلف الذي رقم id له هو 2" في جدول authors. هذا ما يتيح لجدولين يمثّلان أشياء مختلفة — المؤلفين، والكتب التي كتبوها — أن يبقيا مترابطين دون تكرار اسم المؤلف كاملًا في كل كتاب من كتبه. ويمكن لمؤلف واحد أن تشير إليه كتب كثيرة؛ وتُسمّى هذه الصورة علاقة واحد-إلى-متعدد (one-to-many).

Important — this engine does not enforce foreign keys. The in-browser engine (alasql) that powers this course's widgets does not strictly enforce FOREIGN KEY constraints the way a production database would — it will not reject an INSERT whose reference is bad. We still declare and use foreign keys here because the concept, and the query patterns they enable — especially JOIN — are what matter pedagogically.
مهم — هذا المحرّك لا يفرض المفاتيح الأجنبية. المحرّك العامل داخل المتصفّح (alasql) الذي يشغّل أدوات هذا المساق لا يفرض قيود FOREIGN KEY بصرامة كما تفعل قاعدة بيانات إنتاجية — فهو لن يرفض عبارة INSERT ذات مرجع خاطئ. ومع ذلك نُعلن المفاتيح الأجنبية ونستخدمها هنا لأن المفهوم، وأنماط الاستعلام التي يُتيحها — وخاصةً JOIN — هي ما يهمّنا تعليميًا.
Syntax pattern — adding a relationship to an existing table (reusing ALTER TABLE from chapter 2)
نمط الصياغة — إضافة علاقة إلى جدول موجود (بإعادة استخدام ALTER TABLE من الفصل الثاني)
ALTER TABLE child_table ADD COLUMN parent_id_col INTEGER;
UPDATE child_table SET parent_id_col = <parent's id> WHERE id = <child's id>;

أمثلة محلولة — books وauthors

Example 2 — point book 1 at author 2مثال ٢ — توجيه الكتاب 1 إلى المؤلف 2

Book 1 now points at author id 2 (Marcus Reyes).

الكتاب 1 الآن يشير إلى المؤلف رقم 2 (Marcus Reyes).

Example 3 — what does that id refer to?مثال ٣ — إلى ماذا يشير ذلك الرقم؟

author_id doesn't store the author's name — it stores their id, and you look the rest up in authors when you need it. That lookup is what JOIN (lesson 3) automates.

لا يخزّن author_id اسم المؤلف — بل يخزّن رقمه، وتبحث عن الباقي في جدول authors عند الحاجة. وهذا البحث هو ما يُؤتمته JOIN (الدرس الثالث).
