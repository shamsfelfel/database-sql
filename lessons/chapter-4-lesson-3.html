Lesson 3 — IN / NOT IN Subqueries

الدرس ٣ — استعلامات IN / NOT IN

IN widens "equal to one value" into "equal to any value in a list": the subquery after IN may return many rows (still a single column), and the outer row matches if its value appears anywhere in that list. This is the first place we can set a subquery directly beside the Chapter 3 JOIN version of the very same question and compare them.

يوسّع IN عبارة «يساوي قيمة واحدة» إلى «يساوي أي قيمة في قائمة»: فالاستعلام الفرعي الذي يلي IN قد يُعيد صفوفًا كثيرة (بعمود واحد رغم ذلك)، ويتطابق الصف الخارجي إن ظهرت قيمته في أي مكان من تلك القائمة. وهنا لأول مرة يمكننا وضع استعلام فرعي جنبًا إلى جنب مع نسخة JOIN من الفصل الثالث للسؤال نفسه ومقارنتهما.

NOT IN is the negation. But beware: it behaves unexpectedly when the subquery can return a NULL — because comparing anything to NULL is "unknown", NOT IN can silently return no rows at all.

NOT IN هو النفي. لكن انتبه: يتصرّف بشكل غير متوقّع عندما يمكن للاستعلام الفرعي أن يُعيد قيمة NULL — لأن مقارنة أي شيء بـNULL تُعطي «غير معروف»، فقد يُعيد NOT IN بلا صفوف على الإطلاق ودون تحذير.

Syntax pattern
نمط الصياغة
SELECT title FROM books
WHERE author_id IN (SELECT id FROM authors WHERE country = 'Canada');

Worked examples — books and authors

أمثلة محلولة — books وauthors

Example 1 — books by any Canadian author (IN)مثال ١ — كتب أيّ مؤلف كندي (IN)
Example 2 — the same question as a JOINمثال ٢ — السؤال نفسه بصيغة JOIN

Same rows; the JOIN can also return a.name, whereas the IN version can only return books columns.

الصفوف نفسها؛ لكن الـJOIN يستطيع أيضًا إعادة a.name، بينما نسخة IN لا تستطيع إعادة سوى أعمدة books.

Example 3 — books NOT by a Canadian author (NOT IN)مثال ٣ — كتب ليست لمؤلف كندي (NOT IN)
