Lesson 1 — What a View Is — CREATE VIEW

الدرس ١ — ما هو العرض — CREATE VIEW

Some queries are worth keeping. You work out the right SELECT — the columns that matter, the WHERE that filters the noise — and then you need it again tomorrow, and in three other reports. A view is how SQL lets you keep it: you give the query a name, and the database remembers it.

بعض الاستعلامات تستحقّ الحفظ. تصل إلى الـSELECT الصحيح — الأعمدة المهمّة، وWHERE التي تُصفّي الضجيج — ثم تحتاجه غدًا مرّة أخرى، وفي ثلاثة تقارير أخرى. والعرض (View) هو الطريقة التي تتيحها لك SQL لحفظه: تمنح الاستعلام اسمًا، فتتذكّره قاعدة البيانات.

The crucial thing to understand: a view stores the query, not the rows. Nothing is copied. Every time you read the view, the database runs the stored SELECT again against the current data — so a view is always up to date, and it costs no storage.

والأمر الجوهري الذي ينبغي فهمه: العرض يخزّن الاستعلام لا الصفوف. لا يُنسَخ شيء. في كل مرّة تقرأ من العرض تُعيد قاعدة البيانات تنفيذ SELECT المخزّن على البيانات الحالية — فالعرض محدَّث دائمًا، ولا يستهلك مساحة تخزين.

Once the view exists you read it exactly like a table: SELECT * FROM cheap_books, or with your own WHERE and ORDER BY on top. Whoever reads the view does not need to know what is inside it.

وبعد وجود العرض تقرأ منه تمامًا كما تقرأ من جدول: SELECT * FROM cheap_books، أو مع WHERE وORDER BY خاصّين بك فوقه. ومن يقرأ العرض لا يحتاج أن يعرف ما داخله.

Syntax pattern
نمط الصياغة
CREATE VIEW cheap_books AS
SELECT id, title, price
FROM books
WHERE price < 16;

SELECT * FROM cheap_books;
