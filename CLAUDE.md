# Working in this repository

This is **SQL Lab**, a static, bilingual (English/Arabic), offline-first PWA carrying the
two halves of *Introduction to Database* (UCAS): a **practical SQL track** and a
**theory track on database design**. No framework, no CDN, no web font, no analytics.
Served from the repository root on GitHub Pages, and it must work from a `file://` URL.

## Two tracks, one site — and they do not mix

| | Practical — SQL | Theory — Database Design |
|---|---|---|
| pages | `index.html`, `chapters/chapter-N.html`, `lessons/chapter-N-lesson-M.html`, `tests/chapter-N-test.html`, `exams/exam-N.html` | `theory/index.html`, `chapters/tN.html`, `lessons/tN-lesson-MM.html`, `tests/`, `exams/`, `labs/`, `glossary/` |
| assets | `assets/css`, `assets/js` | `assets/theory/css`, `assets/theory/js` |
| storage | `sqllab.*` | `dbt.*` |
| globals | `SQLLAB_DATA`, … | `DBT_REGISTRY`, `DBTBanks`, `DBTTopics`, `DBTGlossary`, … |
| written | by hand | **generated** from `src/` by `build-theory.py` |

Shared on purpose, and only these: `assets/vendor/alasql`, `assets/vendor/fonts`,
`assets/icons`, `assets/img`, `manifest.webmanifest`, `sw.js`.

**If you are working on one track, do not edit the other's files.**

## Never edit a generated file

Generated by `build-theory.py`: `theory/index.html`, `chapters/t*.html`,
`lessons/t*.html`, `tests/t*.html`, `exams/t*.html`, `labs/*`, `glossary/*`,
`assets/theory/js/registry.js`, `assets/theory/js/anchors.js`,
`assets/theory/data/glossary-t*.js`. Generated by `scripts/build-sw.py`: `sw.js`.

Edit the source and rebuild:

```bash
python build-theory.py          # src/ + src/registry.json -> every theory page
python scripts/build-sw.py      # the precache list -- run it last
python tools/verify_chapter.py  # structure, links, parity, banks, activity cadence
```

`scripts/build-sw.py` is vendored byte-for-byte from the hub repository and is the same
file in all seven apps on shamsfelfel.github.io. Everything specific to this course is
in `sw.config.json`, which is data. **Do not edit the script here** — `--check`
re-hashes it and the suite fails if you do.

## The theory track's contract

- `docs/THEORY-CONTENT-PLAN.md` — what each of chapters 2–5 must contain
- `docs/THEORY-AUTHORING.md` — layout, components, question types, **ERD conventions**
- `docs/THEORY-LESSON-BRIEF.md` / `docs/THEORY-QUESTION-BRIEF.md` — how to do it well
- `docs/THEORY-BUILD-RUNNER.md` — the unattended build and its watchdog
- `src/source/` — the lecturer's four decks, transcribed slide by slide. **This is the
  authority for what the chapters teach.** Do not add topics it does not cover and do
  not contradict it from memory.

Two rules outrank the rest, and the verifier enforces both:

1. **Short explanations.** Two paragraphs at most before something happens; no paragraph
   over about sixty words; a definition is one sentence, set apart.
2. **No concept section without something to do.** Every `h2` ends in an inline check, an
   exercise, a live SQL box or an evolve block. Six checks and four exercises per lesson,
   minimum.

ERDs are **authored SVG** in `src/diagrams/<id>.svg`, both languages inside one file,
`currentColor` and theme variables only, no hard-coded colours, no Mermaid, no renderer.

## Bilingual parity is not optional

Every visible sentence exists twice: `<p class="en">` then `<p class="ar">`, inline as
`<span class="en">…</span><span class="ar">…</span>`. Arabic is **written, not machine
translated**, with the English term in parentheses at first use. Code, identifiers,
entity names, SQL and ERDish stay LTR inside `<code>`. An unbalanced pair is a defect the
verifier fails.

## Offline is the point

Nothing may be fetched at run time. No CDN, no Google Fonts, no analytics. To check:

```bash
grep -ri "cdn\|googleapis\|jsdelivr\|unpkg" --include=*.html --include=*.css --include=*.js .
npx playwright test          # e2e/sw-invariants.spec.js, the shared service-worker suite
```

Matches should only ever appear in `README.md`, never in a served page or asset.

## Verify, do not reason

Any SQL output a page quotes must have been run (alasql, in the widget or in node). Any
Oracle convention must match `src/source/`. Do not print output you have not seen.
